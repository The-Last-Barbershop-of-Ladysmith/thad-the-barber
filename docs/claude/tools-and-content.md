# Tools and content

Moved from CLAUDE.md; read it when working in `tools/` or on the gallery and announcements in the media container.

`tools/report-viewer/` — the CI reports viewer (.NET 10 minimal API, issue #137): serves the private `reports` blob container behind App Service authentication (Entra, owner only). `Features/Reports/` (path rules, folder listing, endpoint), `Storage/` (`IReportStore`/`BlobReportStore`), `Infrastructure/` (headers). Tests in the sibling `tools/report-viewer.tests/`: `dotnet test --solution tools/report-viewer/report-viewer.slnx`. Infra is `infra/reports.bicep`, deployed separately from `main.bicep` (it creates Entra objects, which what-if can't preview).

`tools/square-connect/` — the one-time Square OAuth connect (issue #23), stdlib-only Python: `python connect_square.py --env dev` prints the consent link, checks `state` on the pasted redirect URL, exchanges the code and saves `Square--RefreshToken` to that environment's Key Vault under your `az login` (the API only reads it and keeps the access token in memory). Tests: `python -m unittest` from that folder.

`tools/session-token/` — prints a dev session token (issue #162), stdlib-only Python: `python tools/session-token/session_token.py` builds the JWT `POST /api/session` issues and signs it with dev's `session-jwt-signing` key through `az keyvault key sign` (your Crypto User role is on dev's key only). Paste it into Swagger's **Authorize** (the bearer scheme comes from `Infrastructure/OpenApi/Transformers/BearerSecurityTransformer`, which locks only operations that require the token). Tests: `python -m unittest` from that folder.

`tools/square-seed/` — the Square sandbox seed (issue #22), a stdlib-only Python script: `seed.json` mirrors Thad's live Square; dry run by default, `--apply` writes the location and the one service, `--set-token` saves the sandbox token to the dev Key Vault (`Square--SandboxAccessToken`). Booking settings have no write API, so it only checks them and lists Dashboard steps. Tests: `python -m unittest` from that folder (they reuse the API's Square fixtures).

Gallery and content (issues #168, #204) live only in the environment's storage account, edited in the Azure portal, with no copy in the repo and no upload pipeline. The image files are in the media container (`media-<env>`, `publicAccess: 'Blob'`: a file loads by its exact URL, but nobody can list the folder) and `announcements.json` is in the private `content-<env>` container, which only the API reads. The browser reads storage only for the images: `GalleryService` calls the anonymous `GET /api/gallery`, in the browser only, and the API lists `gallery/`: every `.jpg`/`.jpeg`/`.png`/`.webp`/`.avif` shows as uploaded, newest first, with alt text from its file name (`skin-fade_beard.jpg` → "Skin fade beard"); a failed or empty response shows a short "no photos" note in the section, and a placeholder holds it while loading; the gallery is its own feature (`features/gallery/`, `GalleryService`, lazy `gallery` slice registered with `provideState` and its effects on the home route only, so `/book` never requests it), and its nav links always show (BR-32). Announcements (#30) come from the anonymous `GET /api/announcements` (`features/announcements/services/AnnouncementsService`, browser only), which returns only the ones active today on the shop's clock (BR-30) with checked buttons and sanitized `bodyHtml`, their images loading from `announcements/` in the media container; the root `announcements` slice (`features/announcements/state/`, #40, not saved) loads them on the first navigation like `shop`, refreshes them when the home page opens, `announcementsFeature.selectNewestFirst` orders them for the strip and carousel, and `announcementsFeature.selectHomeSections` hides the Announcements nav links on every page when there are none (BR-32). Announcement models are one type per file in `features/announcements/models/`, and the home page's announcements section is `features/announcements/components/announcements-carousel` (`AnnouncementsCarousel`; home only places it, as it does shop's `HoursList`). Reviews (#245) are `reviews.json` in the private `content-<env>` container, read by the API (`Features/Reviews`, `ReviewsService`, anonymous `GET /api/reviews`, cached until the media webhook reports a change, otherwise 60 minutes): `{ score, count, url, testimonials: [{ author, text, rating, source }] }`. `score`, `count` and `url` (https only) are optional and drive the rating line in the hero and the reviews section, which show only when `score` is 0-5 and `count` is a whole number; a testimonial needs an author and text, `rating` defaults to 5 and `source` to "Customer review" (use "Google review" only for verbatim Google reviews). A file that is missing or isn't `{ testimonials: [...] }` is logged and served as no reviews, and an empty or failed load shows a short "no reviews" note in the section, with a placeholder while loading; the reviews are their own feature (`features/reviews/`, `ReviewsService`, lazy `reviews` slice registered with `provideState` and its effects on the home route only, so `/book` never requests them), and the hero reads the rating from it. Their nav link always shows. Google's reviews API replaces this in #37. You have Storage Blob Data Contributor on media-dev and media-test (`canAdminWriteMedia` in `nonprod.bicepparam`) to edit them in the portal or with `az storage blob … --auth-mode login`.
